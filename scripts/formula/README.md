# The formula axis — adding a chapter

`/formula` indexes bank questions by the **identity their SOLUTION uses**, which
is a third axis over the same corpus: `/browse` addresses questions by taxonomy,
`/questions/*` is its cacheable per-chapter counterpart, and this addresses them
by what the working actually does.

Coverage is **chapter by chapter**, deliberately. One chapter is live:
Matrices & Determinants (40 identities, 707 questions).

---

## Why this cannot be automated

Measured, not assumed. A signature classifier was built from the pilot chapter's
own solution text and scored against all 768 hand labels:

**59.2% precision · 45.0% recall.** Exactly **one** of 79 identities cleared a
90%/85% bar — `adj-adj-a`, the only one whose notation (`adj(adj …)`) is
distinctive enough to match on.

Two reasons it fails, both visible in the data:

1. **Naming is not using.** 89 of the 103 questions that name `adj` use a
   *different* adjoint identity. Presence of a token says nothing.
2. **Using is not naming.** The 2023 NDA PYQ on `adj(adj A)` applies it through
   its derived determinant form and never writes the matrix identity at all. One
   operator alone has **five spellings** in this bank (`\text{adj}` 33, bare
   `adj` 23, `\mathrm{adj}` 4, `\operatorname{adj}` 3, `Adj` 1).

So a scan **proposes candidates**; a reader **decides**. Same
lead-is-not-a-verdict discipline as the key audits.

The one thing that would change the economics is an **LLM tagging pass** — the
reading done by the same machinery the grounding and key-audit pipelines already
run at scale. That has not been built.

## The pipeline

### 1. Harvest

```sh
npm run formula:harvest -- "Vectors" "Vector Algebra" --slug=vectors
```

Chapter names differ by exam for the same material (NDA's
`Matrices & Determinants` is MHT-CET's `Determinants and Matrices` and CBSE's
`Matrices` + `Determinants`), so pass every name you want pooled. Writes
`generated-papers/formula-<slug>/batch-NN.txt`, 80 questions each, in a stable
order so a half-finished pass is resumable.

### 2. Read and tag

Read **every** batch. For each question, record the slugs its SOLUTION invokes —
a question legitimately carries several. Write
`scripts/formula/tags/<slug>.json`:

```json
{
  "chapter": "vectors",
  "chapterName": "Vectors",
  "scope": { "exams": ["NDA", "MHT-CET"], "visibility": "PUBLIC", "format": "mcq" },
  "classifiedOn": "2026-MM-DD",
  "method": "Every question read individually; tagged with the identities its SOLUTION uses.",
  "questions": 0,
  "tags": { "<question-uuid>": ["slug-a", "slug-b"] }
}
```

**This file is the expensive artifact.** It is tracked precisely because it
cannot be regenerated by a machine.

Conventions that matter:

- Reuse an existing slug when the identity is the same one. Slugs are global.
- `direct-computation` for a solution that invokes no identity — it keeps the
  denominator honest and is excluded from publication by definition.
- Tag what the solution **does**, not what the stem is about.

### 3. Author the metadata

`scripts/formula/meta/<slug>.ts` exports `META`, one entry per slug you want
published: `name`, `kind`, `latex`, `statement`, `symbols`.

- `kind` is `formula` | `property` | `technique`. Not everything is a formula:
  `A^T = A` is a property, cofactor expansion is a technique. Saying which is
  more useful than flattening all three.
- `statement` is **plain text, no LaTeX** — it feeds `<meta description>`,
  where LaTeX leaks through as raw markup.
- A slug with no `META` entry is simply not published. That is how the long
  tail is withheld.

### 4. Generate

```sh
npm run formula:generate -- vectors
```

Pure: tags + meta → `src/lib/formula/<slug>.ts`. No database, deterministic,
safe to re-run. It refuses if `META` names a slug the tags do not contain (a
rename or a typo), and reports any slug over the floor that you have not
authored yet.

### 5. Register

Add the chapter to `FORMULA_CHAPTERS` in `src/lib/formula/index.ts` — chapter
name, exam, and the `/notes` href if that chapter has notes. The pages, the
sitemap and the index all derive from that list.

### 6. Gate

```sh
npm run prepush
```

`tests/formula-registry.test.ts` pins the structural invariants and the
Matrices & Determinants counts. **Update that pin deliberately** when a chapter
lands — it exists so a re-tag cannot change what the pages claim silently.

## The publishing floor

**12 questions.** Below it an identity is withheld rather than shipped as a thin
page: a page with four questions on it is not a drill. The pilot chapter yielded
79 identities, of which 40 clear the floor and cover 707 of 768 questions.

The number lives in `generate-registry.ts` and is quoted to the reader on
`/formula`. Changing one means changing the other.

---

## Known limits

- **Dense pages are long.** `cofactor-expansion` renders 99 cards (~2.3 MB).
  The exam and PYQ/Practice filters help; pagination does not exist yet.
- **Filters are client-side and not in the URL**, so a filtered view is not
  shareable. That is deliberate — see the note in `src/lib/formula/filters.ts`.
- **One chapter of 883.** At the measured cost this is a long project by hand.
